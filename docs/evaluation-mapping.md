# 评估的各次转换与插值函数（v2.6.1）

本文记录从引擎评分到面板分数的完整转换。旧尺度和中间值只用于说明公式，产品面板只显示本版最终分数。普通评分与杀棋分开处理：杀棋类型直接保留“杀棋 N”，不经过以下普通评分转换或分档。

## “系统数值”和百分兵分是什么

本功能的数学输入来自引擎结果对象的 `score`：当 `score.type = "cp"` 时，取 `score.value` 作为以下公式中的 `cp`。例如 `score = {type: "cp", value: 22}` 的输入就是 22。这里的 cp 是 centipawn，中文常称“百分兵分”，是引擎表达局面好坏的评分单位：`100 cp` 对应旧版面板的 `1.00`。它不是百分比，不是胜率，也不表示棋盘上实际多了一个兵；评分综合子力、位置和搜索结果。

正负方向沿用引擎本次搜索开始时的行棋方视角：正值表示该视角更有利，负值表示更不利。本次显示转换不把评分改成红方固定视角。`score.type = "mate"` 则属于杀棋报告，直接显示“杀棋 N”，不能把它的 `value` 当 cp 代入普通评分公式。无有效有限评分时显示“评估 -”。

## 引擎怎样产生 cp

可以把过程理解为三层：**NNUE 对搜索到的局面给出内部评估，搜索比较双方后续走法并回传内部值 `v`，最后引擎把 `v` 换算成对外报告的 cp**。这里的 cp 来自随插件打包的官方 Pikafish，不是本插件另造一套“车几分、马几分”的固定加权公式。

本版使用的上游固定为 [`official-pikafish/Pikafish` 提交 `6a59ee2f7b105bff64d9efc2692591107787e2b1`](https://github.com/official-pikafish/Pikafish/tree/6a59ee2f7b105bff64d9efc2692591107787e2b1)，以下公式对应这份源码。

**第一层是局面的静态评估。** [`src/evaluate.cpp`](https://github.com/official-pikafish/Pikafish/blob/6a59ee2f7b105bff64d9efc2692591107787e2b1/src/evaluate.cpp#L42) 调用 `network.evaluate(...)`，取得 `psqt` 与 `positional` 两部分，先相加为 `nnue`，再按复杂度、子力状态、搜索使用的 `optimism` 和规则计数修正：

```text
(psqt, positional) = network.evaluate(局面, 累加器, 缓存)
nnue = psqt + positional
complexity = |psqt - positional|
optimism ← optimism + optimism × complexity / 467
nnue ← nnue - nnue × complexity / 11698
material = pos.major_material()
v_leaf = nnue + (nnue × material + optimism × 13371) / 36220
v_leaf ← v_leaf - v_leaf × pos.rule60_count() / 244
```

源码在这些步骤使用整数运算，最后还把普通静态评估限制在杀棋值范围之外。`psqt` 和 `positional` 依赖实际 NNUE 网络及其训练权重；规则计数修正使长期无进展局面的评价衰减。这里的 `material = pos.major_material()` 是静态评估使用的子力量，和下文对外换算的 `M` 是两个不同变量，不能混用。

**第二层是搜索。** 最终向外报告的 `v` 不是简单把当前棋盘的 `v_leaf` 原封不动输出。引擎使用 Negamax / Alpha-Beta、迭代加深和选择性搜索，比较我方着法以及对方回应，在叶节点或静态搜索中调用评估，再向根节点回传结果。相关代码见 [`src/search.cpp` 的搜索回传](https://github.com/official-pikafish/Pikafish/blob/6a59ee2f7b105bff64d9efc2692591107787e2b1/src/search.cpp#L1301) 和 [对静态评估的调用](https://github.com/official-pikafish/Pikafish/blob/6a59ee2f7b105bff64d9efc2692591107787e2b1/src/search.cpp#L1837)。因此搜索深度、可用时间、实际分支及网络权重都可能影响最终内部评分；不能只凭六个棋子权重手算出任意局面的全部 cp。

**第三层是内部值到 cp 的确定换算。** [`src/score.cpp`](https://github.com/official-pikafish/Pikafish/blob/6a59ee2f7b105bff64d9efc2692591107787e2b1/src/score.cpp#L29) 将普通、非决定性内部值交给 `UCIEngine::to_cp(v, pos)`，决定性值则走独立杀棋分支。普通 cp 换算的完整公式来自 [`src/uci.cpp` 的局面参数](https://github.com/official-pikafish/Pikafish/blob/6a59ee2f7b105bff64d9efc2692591107787e2b1/src/uci.cpp#L535) 和 [`to_cp`](https://github.com/official-pikafish/Pikafish/blob/6a59ee2f7b105bff64d9efc2692591107787e2b1/src/uci.cpp#L578)：

```text
M = 10 N_R + 5 N_N + 5 N_C + 3 N_B + 2 N_A + N_P
m = clamp(M, 17, 110) / 65
a(m) = 220.59891365 m³ - 810.35730430 m²
     + 928.68185198 m + 79.83955423
cp = round(100 v / a(m))
```

`N_R、N_N、N_C、N_B、N_A、N_P` 分别为棋盘上**双方合计**的车、马、炮、象、士、兵数量，不是我方数量减对方数量；将帅不计入这个 `M`。`clamp` 将 `M` 限制在 17 至 110，`round` 对应源码的 `std::round`，半整数按远离零方向取整。这里的子力加权用于确定评分尺度 `a(m)`，不是直接给局面胜负打分。例如 `M = 65` 时，`m = 1`、`a(1) = 418.76301556`，普通内部值 `v = 418` 换算为 `round(100 × 418 / 418.76301556) = 100 cp`；还需要前两层才能知道某个真实局面会产生什么 `v`。

源码中这套对外尺度与引擎自己的拟合 WDL 参数有关，但本插件后续的 tanh 和 PCHIP 是显示转换，不能据此反推某一真实棋局的准确胜率。透明说明的含义是每层来源和转换可核对，不是声称复杂的 NNUE 与搜索能压缩成一个无需网络权重、无需搜索就可手算的简单公式。

## 完整转换链

令 `cp` 为引擎原始百分兵分，允许任意有限实数。依次执行：

1. **单位换算**：`x = cp / 100`，即 2.6.0 以前面板使用的尺度。
2. **解析变换**：`u = tanh(1.5 × x) = tanh(0.015 × cp)`，即 2.6.0 尚未舍入、尚未钳制的评分。`tanh(z) = (exp(2z) - 1) / (exp(2z) + 1)`；实际数值实现使用双曲正切函数。尺度系数 1.5 不限制输入范围。
3. **PCHIP 插值**：令 `b = |u|`，计算 `y = sign(u) × P(b)`，且 `sign(0) = 0`。插值输入是第二步的 `u`，不直接使用 `cp`，也不使用上一版六位显示值。
4. **显示**：对普通有限评分限制到 `[-0.999999, 0.999999]`，固定六位小数；零统一显示为 `0.000000`。按该最终显示值的绝对值分档。

前两次转换都不是插值，第三次转换才使用五段三次多项式。tanh 的数学输出在 `(-1, 1)` 内，浮点运算可能在极端输入时得到 ±1，因此仍保留端点和显示钳制。不同的大评分可因浮点饱和、六位舍入或钳制显示相同；转换不增加引擎精度，不参与引擎搜索、着法排序或时间分配，也不代表校准胜率。

## 六个精确节点

以 `X_i` 为输入绝对值、`Y_i` 为输出绝对值，使用以下十进制字面值，不重新计算四个中间横坐标，也不把它们先舍入成六位小数：

| 节点 `i` | `X_i` | `Y_i` |
| --- | --- | --- |
| 0 | 0 | 0 |
| 1 | 0.635148952387 | 0.5 |
| 2 | 0.978026114739 | 0.7 |
| 3 | 0.999753210848 | 0.9 |
| 4 | 0.999999969540 | 0.99 |
| 5 | 1 | 1 |

满足 `P(X_i) = Y_i`。负半轴通过 `F(-b) = -P(b)` 延拓，正负方向对称。端点补全为 `(0, 0)` 与 `(1, 1)`，无需在 `[0, 1]` 外做外推。

## 节点斜率

令区间宽度和割线斜率为：

```text
h_i = X_(i+1) - X_i
δ_i = (Y_(i+1) - Y_i) / h_i                 i = 0, …, 4
```

节点一阶导数记为 `d_i`。内部节点 `i = 1, …, 4` 使用 Fritsch–Butland 加权调和平均：若相邻割线有任一个为零，或符号不同，则 `d_i = 0`；否则：

```text
w1 = 2 h_i + h_(i-1)
w2 = h_i + 2 h_(i-1)
d_i = (w1 + w2) / (w1 / δ_(i-1) + w2 / δ_i)
```

左端点先作单边估计：

```text
d_0* = ((2 h_0 + h_1) δ_0 - h_0 δ_1) / (h_0 + h_1)
```

右端点对称处理：

```text
d_5* = ((2 h_4 + h_3) δ_4 - h_4 δ_3) / (h_4 + h_3)
```

采用与 SciPy `PchipInterpolator` 相同的端点限制规则。以左端为例：若 `d_0*` 与 `δ_0` 符号不同，设 `d_0 = 0`；否则，若 `δ_0` 与 `δ_1` 符号不同且 `|d_0*| > 3|δ_0|`，设 `d_0 = 3δ_0`；其余情况取 `d_0 = d_0*`。右端交换相邻下标后使用相同规则。本组节点的割线均为正。

对本组节点，上述规则得到以下参考斜率（对 `b` 求导）：

| 节点 `i` | `d_i` |
| --- | --- |
| 0 | 0.9196449521966364 |
| 1 | 0.6603012392333599 |
| 2 | 1.4797679604891136 |
| 3 | 26.01724018542384 |
| 4 | 1091.6262809772932 |
| 5 | 328339.88482224976 |

端点估计在本组数据中无需额外截断。最后几个斜率较大，来自接近 1 处极窄的输入区间；这不表示引擎突然增加了评估精度。

## 五个区间的插值函数

当 `b ∈ [X_i, X_(i+1)]` 时，令局部参数 `t = (b - X_i) / h_i`。每个区间都使用同一形式的三次 Hermite 函数：

```text
H00(t) = 2t³ - 3t² + 1
H10(t) = t³ - 2t² + t
H01(t) = -2t³ + 3t²
H11(t) = t³ - t²

P_i(b) = H00(t) Y_i + H10(t) h_i d_i
       + H01(t) Y_(i+1) + H11(t) h_i d_(i+1)
```

等价的局部多项式为：

```text
P_i(b) = A_i t³ + B_i t² + C_i t + D_i
A_i = 2Y_i - 2Y_(i+1) + h_i(d_i + d_(i+1))
B_i = -3Y_i + 3Y_(i+1) - h_i(2d_i + d_(i+1))
C_i = h_i d_i
D_i = Y_i
```

`i = 0, …, 4` 分别对应 `[0, 0.635148952387]`、`[0.635148952387, 0.978026114739]`、`[0.978026114739, 0.999753210848]`、`[0.999753210848, 0.999999969540]` 和 `[0.999999969540, 1]`。节点处左右函数值与一阶导数相同；二阶导数不要求连续。最后区间很窄，使用局部 `t` 而不是直接展开 `b` 的高次幂，可以避免产生不必要的巨大全局系数。

五个区间的局部参数分别为：

| `i` | `b` 所在区间 | `t_i` |
| --- | --- | --- |
| 0 | `[0, 0.635148952387]` | `b / 0.635148952387` |
| 1 | `[0.635148952387, 0.978026114739]` | `(b - 0.635148952387) / (0.978026114739 - 0.635148952387)` |
| 2 | `[0.978026114739, 0.999753210848]` | `(b - 0.978026114739) / (0.999753210848 - 0.978026114739)` |
| 3 | `[0.999753210848, 0.999999969540]` | `(b - 0.999753210848) / (0.999999969540 - 0.999753210848)` |
| 4 | `[0.999999969540, 1]` | `(b - 0.999999969540) / (1 - 0.999999969540)` |

对应 `P_i(b) = A_i t_i³ + B_i t_i² + C_i t_i + D_i` 的系数如下。数值保留双精度参考输出；以节点和斜率算法为定义，运行时动态生成系数。

| `i` | `A_i` | `B_i` | `C_i` | `D_i` |
| --- | --- | --- | --- | --- |
| 0 | 0.003501168314592769 | -0.08761269627027911 | 0.5841115279556863 | 0 |
| 1 | 0.3337808544377575 | -0.36018306964360114 | 0.22640221520584358 | 0.5 |
| 2 | 0.19743013869620432 | -0.029581199392770027 | 0.03215106069656577 | 0.7 |
| 3 | 0.09578825340447801 | -0.012208233562085181 | 0.006419980157607156 | 0.9 |
| 4 | -0.009965516182746442 | 0.01993226524626417 | 0.00003325093648228132 | 0.99 |

逐段写出即为：

```text
P_0(b) = 0.003501168314592769 t_0³ - 0.08761269627027911 t_0²
       + 0.5841115279556863 t_0

P_1(b) = 0.3337808544377575 t_1³ - 0.36018306964360114 t_1²
       + 0.22640221520584358 t_1 + 0.5

P_2(b) = 0.19743013869620432 t_2³ - 0.029581199392770027 t_2²
       + 0.03215106069656577 t_2 + 0.7

P_3(b) = 0.09578825340447801 t_3³ - 0.012208233562085181 t_3²
       + 0.006419980157607156 t_3 + 0.9

P_4(b) = -0.009965516182746442 t_4³ + 0.01993226524626417 t_4²
       + 0.00003325093648228132 t_4 + 0.99
```

实现中用 Horner 形式 `((A_i t + B_i) t + C_i) t + D_i` 求值。相邻区间在公共节点上给出相同函数值和一阶导数，因此节点归入任一相邻段都保持连续。

## 从系统数值 22 到面板 +0.271334 的完整复算

给定 `score = {type: "cp", value: 22}`，各步如下。下面列出足以独立复算的小数，浮点实现最后几位可能有微小差异，六位显示结果相同。

```text
1. 原始输入：cp = 22
2. 旧尺度：x = 22 / 100 = 0.22
3. 上一版未舍入评分：
   u = tanh(1.5 × 0.22) = tanh(0.33)
     ≈ 0.31852077690277081
4. b = |u| = 0.31852077690277081
   b 位于第 0 段 [0, 0.635148952387]
   t_0 = (b - 0) / 0.635148952387
       ≈ 0.50148988785341531
5. 代入第 0 段：
   P_0(b) = 0.003501168314592769 t_0³
          - 0.08761269627027911 t_0²
          + 0.5841115279556863 t_0
          ≈ 0.00044156996967228306
            - 0.02203390163921604
            + 0.2929260246483842
          ≈ 0.27133369297884041
6. y = sign(u) × P_0(|u|) = +0.27133369297884041
   数值未触及 ±0.999999，钳制不改变它。
7. 固定六位：+0.271334
   最终显示绝对值 0.271334 < 0.5，分档为“均势”。
```

因此本版面板为 **“评估 +0.271334”** 和 **“均势”**。若输入是 `cp = -22`，则 `u`、`y` 和最终分数逐项取反，面板为“评估 -0.271334”，仍属均势。这里没有把 cp=22 直接塞入六节点插值，也没有对 `u` 先保留六位后再插值。

## 为什么选 PCHIP

线性插值可以准确通过节点并保持单调，但节点处通常有斜率折角。自然三次样条追求二阶连续，端点二阶导数为零，却不保证保留本组高度不均匀节点的单调形状，可能过冲或产生局部回折。PCHIP 用受限制的一阶斜率形成分段三次 Hermite 曲线，准确通过节点、保持单调且避免区间过冲，同时保留一阶连续，适合这里的评分重标度。选择它是为了形状约束，不是声称它在任何数据上都比其他插值误差更小。

运行时使用同一组节点及斜率规则，不依赖 Python 或 SciPy。SciPy 仅作为开发期的独立数值参考，用于核对节点、斜率、局部系数与区间输出。在本组节点上，等距密集取样的自然三次样条出现明显过冲和回折，PCHIP 保持单调；这是对这组节点的参考比较，不是对所有数据的普遍结论。

## 六位显示与局势分档

令 `q` 为最终六位显示分数的绝对值，使用以下四个分界、五个区间：

| 最终六位绝对值 `q` | 正分 / 负分分档 |
| --- | --- |
| `q < 0.5` | 均势 |
| `0.5 ≤ q < 0.7` | 稍优 / 稍劣 |
| `0.7 ≤ q < 0.9` | 明显优势 / 明显劣势 |
| `0.9 ≤ q < 0.99` | 大幅优势 / 大幅劣势 |
| `q ≥ 0.99` | 接近胜势 / 接近败势 |

这里不再沿用 2.6.0 按原始评分判断分档的方式：显示值舍入到某边界时，就进入该边界起始的区间，以保证文字与分数一致。“接近胜势”仍是启发式描述，不是获胜证明；普通评分接近 ±1 也不等于引擎报告杀棋。
